## Using the bindings

- `npm i spacetimedb@2.10.*` in your package (bindings import `spacetimedb`).
- Casing and every reducer's arguments: CONTRACT.md → "Generated casing".
- Local: `spacetime start`, then `cd spacetimedb && npm i && npm run publish:local`. URI `ws://127.0.0.1:3000`, db `sprout`.
- CLI gotcha: the default server is maincloud; pass `--server local` before positional args.
- SQL can't filter on option columns (`WHERE path = 'x'` fails when `path` is optional). Subscribe to the whole table and filter on the client.

## Behaviour notes (for consumers)

- Unknown handles are auto-joined on first event (free color picked). A paused member's ingest/test/diff events are dropped silently.
- `ingestActivity` accepts only client kinds. `commit`, `claim`, `release`, `test_*`, `message_*`, `handoff_*` and `certify_*` are written by the module itself and rejected from clients.
- Plants: idle 3h → `dormant` (not blooms); any activity or re-seed wakes them. create → `seed`; any other activity on a seed → `sprout`; edit/file_change → `growing`; **any recorded diff → `bud`** (a bloom goes back to bud); botanist OK → `bloom`. The contract never said what makes a bud, so this is my rule.
- `commit` activity: one per bed, `path` = bed name (`src`, `(root)`), detail `abc1234: 2 files in src`.
- Bugs: plants whose `lastTouchedBy` is the tester and that changed since their last bloom.
- Botanist repo: one database = one team repo. The "same repo" check uses the repo of the most recent test run.
- `submitEvidence` never returns data. Read the newest `certification` row for (handle, path): `result` is `bloom` or `refused`, and `reason` is the plain-English list of what's missing (joined by `; `).
- Claim conflict error text: `src/api/auth.ts is fenced by ivy (claim on src/api/) until 4:56pm (in 20 min). Use post_finding to ask them, or work elsewhere.`
- `reportStatus` without sessionId updates all of that member's live claude agents. If they have none, it creates `<handle>:mcp`.
- `shared/botanist.ts` and `shared/constants.ts` are imported directly by the module (bundling `../shared` works), so there's no copy to keep in sync.

## Best Use of SpacetimeDB (draft)

Sprout keeps every piece of shared live state in one SpacetimeDB database: who is online, what each agent is doing, every plant in the garden, the claims, the messages between agents, the handoffs, and the botanist's verdicts. The rules live in reducers, not in a server we wrote: claim conflicts, message delivery, handoffs, test-driven bugs and the evidence gate that decides when a plant may bloom all run as transactions inside the database, so no client can bend them, and scheduled reducers expire stale claims and put idle agents to sleep. The 3D garden in the browser subscribes to the tables directly, with no API layer, and every reducer call shows up on the projector within a frame. The `activity` table is both the live feed and the replayable timelapse of the hackathon. Our only server-side code besides the module is a thin MCP adapter, and it reads the same subscription cache as the garden.
