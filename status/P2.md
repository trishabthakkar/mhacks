## Deploy (integrator)

- Ready: `infra/deploy.sh ubuntu@<vm-ip>`. The unit's `npm ci && npm run build && npm start` in `mcp/` is what I tested.
- `/etc/sprout/mcp.env` must say (setup-vm.sh defaults `SPROUT_DB=sprout`, which is wrong):
  ```
  PORT=8080
  SPROUT_STDB_URI=wss://maincloud.spacetimedb.com
  SPROUT_DB=sprout-mhacks
  ```
  Verified 5:15pm: the built server connects to Maincloud `sprout-mhacks` (`/health` → `"db":"connected","impl":"spacetimedb"`). Without these it runs on the fake db (`"impl":"fake"`).
- No Host allow-list needed behind Caddy: the server accepts proxied requests (`X-Forwarded-For`). The SDK's default would have 403'd `*.sslip.io`.
- **Risk:** `*.sslip.io` isn't on the Public Suffix List, so every sslip.io user shares one Let's Encrypt rate limit; cert issuance can fail. If `journalctl -u caddy` shows rate-limit errors, use the `.tech` domain or a DuckDNS name (duckdns.org is on the PSL). Details in `mcp/NOTES-P2.md`.
